# ADR-024: скриптуемый режим — сообщения из shell и с серверов

Статус: **принято** (владелец, 2026-11-16). English version: [024-scriptable-mode.md](024-scriptable-mode.md).

## Контекст

termchat.app сейчас — интерактивные приложения: TUI, desktop и Android. Но у терминала есть ещё одна сторона: скрипты, cron, CI и серверы. Типичные задачи:

- «бэкап не прошёл» с сервера на телефон;
- «сборка закончилась» после долгой команды;
- прочитать в скрипте ответ человека («да, перезапускай»).

Сейчас для этого ставят Telegram-ботов, ntfy или почту. Почти везде текст лежит открытым у третьей стороны, а для бота нужен аккаунт с номером телефона у его владельца. Сквозного шифрования из скрипта без своей инфраструктуры почти нет.

У termchat.app для этого уже есть всё, кроме входа из командной строки: engine без интерфейса, анонимные очереди (ADR-023), Tor, отдельные личности через `TERMCHAT_HOME`.

## Решение

### 1. Подкоманды того же бинарника

`termchat` без аргументов по-прежнему запускает TUI. С подкомандой — работает без интерфейса и завершается:

```
termchat init --nickname NAME [--relay URL] [--onion URL] [--tor]
termchat invite                       # одноразовое приглашение в stdout
termchat add INVITE                   # добавить контакт по приглашению
termchat contacts                     # имя, отпечаток, состояние; по строке на контакт
termchat send CONTACT [TEXT]          # TEXT или stdin, если TEXT не задан
termchat send-file CONTACT PATH
termchat recv [--from CONTACT] [--wait SECS] [--follow] [--json] [--save-dir DIR]
```

- Папка состояния — как сейчас: `TERMCHAT_HOME` или `~/.termchat`. Для сервера заводится отдельная личность в своей папке.
- `CONTACT` — имя, которое показывает приложение (ник или локальное имя), или начало отпечатка. Если подходит больше одного контакта — ошибка, ничего не отправляется.
- Отправка всегда одному контакту. Отправки «всем контактам» нет (правило 15: никаких рассылок).
- Команды принять запрос контакта нет. Связь заводится так: личность на сервере добавляет приглашение владельца (`termchat add`), владелец принимает запрос на телефоне. Тогда серверная личность не может сама впустить незнакомца.

### 2. Пароль без интерфейса

Файл состояния зашифрован паролем (ADR-003), а скрипту ввести его некому. Источники, в порядке предпочтения:

- `--password-file PATH`: файл должен принадлежать текущему пользователю и иметь права `0600`, иначе ошибка. Подходит и для `LoadCredential=` в systemd: там файл появляется только у службы.
- `--password-stdin`: первая строка stdin. Тогда текст для `send` берётся из аргумента.
- Интерактивный ввод с терминала без эха, если stdin — терминал и другой источник не задан.

Переменной окружения для пароля нет: окружение наследуют все дочерние процессы, и его может прочитать любой процесс того же пользователя.

Пароль под принуждением работает и здесь (ADR-003): если он пришёл из файла, данные молча стираются, а команда завершается как при неверном пароле.

### 3. Доставка и коды возврата

`send` подключается, отправляет и ждёт `Accepted` от relay (по умолчанию до 60 секунд, `--timeout SECS`).

| Код | Значение |
|---|---|
| 0 | сообщение на relay |
| 1 | неверный пароль, нет состояния, ошибка ввода |
| 2 | ошибка в аргументах |
| 3 | контакт не найден, или подходит больше одного |
| 4 | relay не принял сообщение за отведённое время; оно осталось в очереди и уйдёт при следующем запуске любой команды |
| 5 | отправить нельзя: контакт ушёл, заблокирован или нужен новый адрес (ADR-023) |

С Tor первое подключение занимает 10–30 секунд. Для редких уведомлений это нормально. Режима службы, который держал бы соединение открытым, нет (решение 1 ниже).

### 4. Вывод `recv`

- По умолчанию печатает непрочитанные сообщения, каждое одной записью, и отмечает их прочитанными. `--wait SECS` ждёт хотя бы одно; `--follow` не завершается и печатает новые по мере прихода.
- Текст от собеседника перед выводом очищается так же, как в TUI: без управляющих символов и bidi-символов (`clean_text`). Иначе собеседник мог бы послать escape-последовательность в чужой терминал или в лог.
- `--json`: по объекту на строку (`{"from": ..., "fingerprint": ..., "at": ..., "text": ...}`), текст экранирован JSON'ом. Для разбора в скриптах.
- Файлы (ADR-017) сохраняются только с явным `--save-dir`, под безопасным именем (`safe_name`), никогда не перезаписывая существующие и ничего не открывая. Без `--save-dir` выводится только строка «пришёл файл NAME, SIZE».
- Запросы контактов в выводе не показываются: их тексты скрыты до принятия, как в приложениях (ADR-007).

### 5. Вместе с открытым приложением

Файл состояния занимает один процесс (`data::lock`). Если TUI или другая команда уже открыли эту личность, команда сразу завершается с кодом 1 и сообщением, а не ждёт. Поэтому для скриптов — своя личность, а не основная.

### 6. Что меняется в коде

- `client`: разбор подкоманд и режим без TUI. Всё остальное — существующий `Engine` (`setup`, `unlock`, `invite`, `add`, `send`, `send_file`, `on_relay`, `tick`).
- `engine`: поиск контакта по имени или отпечатку, «непрочитанные с момента» для `recv`. Протокол, relay и `core` не меняются.
- Документация: раздел в README с примерами (cron, systemd, конец долгой команды), строка в модели угроз.

## Модель угроз

- **Личность на сервере так же сильна, как сервер.** Пароль лежит рядом с файлом состояния, поэтому кто получил root на сервере, читает всю переписку этой личности и может писать от её имени. Это записывается честно: серверу — отдельная личность, которая говорит только с владельцем, и никогда не основная.
- **Контакты владельца не страдают.** Серверная личность — отдельный ключ и отдельные очереди (ADR-023); через неё нельзя добраться до основной личности владельца.
- **Relay видит то же, что и для людей:** очередь, время, размер. То, что пишет скрипт, а не человек, может угадываться по времени (cron ровно в 03:00).
- **Вывод — данные от собеседника.** Очистка текста и запрет автоматического открытия файлов защищают терминал и скрипт, который этот вывод читает.

## Это не новый криптопротокол (правило 1)

Те же сессии Olm, те же очереди и кадры. Меняется только способ запуска клиента.

## Отклонено

- **Пароль в переменной окружения:** см. раздел 2.
- **HTTP API или webhook на устройстве:** открытый порт — ещё одна поверхность атаки и путь для посторонних. Скрипт вызывает `termchat` напрямую.
- **Отправка всем контактам или группе:** это рассылка (правило 15).
- **Принятие запросов из командной строки:** серверная личность не должна впускать незнакомцев; связь заводит человек со своего устройства.
- **Отдельный бинарник для скриптов:** лишний артефакт в релизе; подкоманды достаточно.

## Решения владельца (2026-11-16)

1. **Режима службы нет.** Долгоживущий процесс с паролем в памяти не делаем; каждая команда подключается сама. Вернуться, если попросят.
2. **Интерактивный ввод пароля есть** в первой версии: с терминала без эха, когда stdin — терминал и другой источник не задан.
3. **Пароль под принуждением из файла стирает данные** молча, как в приложениях (ADR-003).
4. **Контакт-скрипт не помечается** в desktop и Android: это обычный контакт с выбранным ником.
