# ADR-025: ответы, правка, удаление и реакции

Статус: **принято** (владелец, 2026-11-17). English version: [025-replies-edits-reactions.md](025-replies-edits-reactions.md).

## Контекст

От любого мессенджера ждут четырёх вещей, и в termchat.app нет ни одной:

- **ответить** на конкретное сообщение;
- **исправить** уже отправленное сообщение (опечатка, не та цифра);
- **удалить** своё сообщение и у собеседника;
- **отреагировать** на сообщение, не набирая нового.

Все четыре происходят между двумя людьми, внутри шифрования, которое у чата уже есть. Relay не должен узнать ничего нового, новая криптография не нужна. Сначала нужно решить две проблемы:

1. **У сообщения нет имени.** `Inner.seq` считается отдельно для каждой сессии Olm и каждого направления и начинается заново с каждой новой сессией, поэтому указать им на сообщение нельзя. У `Body::Text` идентификатора нет совсем.
2. **Старые клиенты не читают новые виды сообщений.** postcard декодирует `Inner` целиком. Незнакомый вариант тела делает всё сообщение «malformed»: клиент пишет в строке состояния «a message could not be decrypted», а следующее сообщение сообщает «1 message lost», потому что этот `seq` не был принят.

Правило 9 (ADR-017) остаётся: без разметки, превью и картинок. Ответ — это указатель, а не цитата; реакция — один из нескольких заранее заданных знаков.

## Решение

### 1. Новый вид текста, с идентификатором

```rust
Body::Message {
    id: u64,                 // случайный, выбирает отправитель
    sent_at: u64,
    expires_in: Option<u32>,
    reply_to: Option<Ref>,
    text: String,            // MAX_TEXT_BYTES, как у Text
}

struct Ref { id: u64, theirs: bool }
```

- `id` берётся из генератора случайных чисел операционной системы (`getrandom`), 64 бита. Это имя, а не секрет.
- Каждая сторона называет свои сообщения сама. `Ref.theirs` говорит, чьё сообщение имеется в виду, с точки зрения отправителя `Ref`: `false` — своё, `true` — получателя. Поэтому собеседник не сможет указать на наше сообщение, повторив его id среди своих, а случайные id разных сторон не пересекаются.
- `Body::Text` остаётся для контактов со старыми клиентами (раздел 6).

### 2. Ответы

`reply_to` указывает на сообщение; **цитируемый текст не копируется**. Приложение показывает цитату из своей копии. Если копии нет (истекла, удалена, не дошла), оно пишет «ответ на сообщение, которого уже нет». Так ответ никогда не продлевает жизнь тексту исчезающего сообщения.

### 3. Правка

```rust
Body::Edit { id: u64, text: String }
```

- Только своего `Message`. Получатель ищет `id` только среди сообщений отправителя; всё остальное молча игнорируется.
- Исправленное сообщение сохраняет свой таймер (`expires_at` не сдвигается) и получает пометку «изменено». **История не хранится:** старый текст затирается (`zeroize`), как у любого уходящего сообщения.
- Правка уже истёкшего или удалённого сообщения игнорируется.
- Файлы не правятся.

### 4. Удаление

```rust
Body::Delete { id: u64 }
```

- Только своего `Message`; файлы позже (решение 3).
- Получатель затирает текст и оставляет строку «сообщение удалено», чтобы было видно, что что-то убрали.
- Честно, в приложении и документации: **удаление — это просьба.** Изменённый клиент, скриншот или резервная копия сохранят то, что сохранили. Текст говорит «удалено у обоих», а не «удалено везде».

### 5. Реакции

```rust
Body::React { target: Ref, reaction: Option<u8> }
```

- **Фиксированный набор** из семи, по номеру: нравится, люблю, смешно, ого, грустно, спасибо, не нравится (в смысле 👍 ❤️ 😂 😮 😢 🙏 👎). `None` убирает свою реакцию. Номер вне набора игнорируется.
- **Рисует их termchat.app, а не шрифт эмодзи**, пиксельными спрайтами в духе аркад 80-х с мягким свечением, в цветах темы («не нравится» — красная стрелка вниз): одна и та же картинка на любом устройстве. В терминале — знаки шириной в одну колонку (▲ ♥ ☺ ◎ ☹ ✧ ▼). По сети передаётся только номер, поэтому рисунок можно менять без изменения протокола.
- Одна реакция от человека на сообщение; новая заменяет старую.
- Произвольный текст или любой эмодзи в качестве реакции не допускаются: это был бы второй текстовый канал в обход всех лимитов, а произвольные эмодзи ломают ширину колонок в терминале.
- Реакция живёт вместе с сообщением: истекает и удаляется с ним.

### 6. Старые клиенты: сказать, что понимаешь, один раз

```rust
Body::Understands { level: u16 }    // 1 = этот ADR
```

- Обновлённый клиент один раз отправляет `Understands { level: 1 }` каждому контакту: при первом подключении после обновления, а новому контакту — сразу после `ContactRequest` / `ContactAccept`. Уровень хранится для каждого контакта.
- Контакту, который ещё не сказал «уровень 1», клиент отправляет только `Text`, и приложение не предлагает в этом чате ответ, правку, удаление и реакции. Один раз объясняет почему: «у собеседника старая версия; ответы и реакции появятся после его обновления».
- **Цена:** контакт на 0.8 или старше, когда придёт `Understands`, увидит одну строку в строке состояния «a message could not be decrypted (malformed)» и одну строку «1 message lost» в чате. На деле ничего не потеряно. Об этом говорится в примечаниях к выпуску.

### 7. Дальше незнакомые виды пропускаются молча

Клиент декодирует заголовок `Inner` (`sender`, `recipient`, `seq`) отдельно от тела. Если тело незнакомого вида, клиент принимает `seq`, ничего не показывает и работает дальше. Со следующего выпуска новый вид сообщения ничего не стоит старым клиентам, а цена из раздела 6 платится только один раз.

### 8. Хранение и скриптуемый режим

- `Msg` получает `id`, `reply_to`, `edited` и две реакции (`#[serde(default)]`: старые файлы читаются как раньше; на их сообщения просто нельзя ответить).
- `termchat recv --json` получает поля `"id"` и `"reply_to"` и печатает правки, удаления и реакции как отдельные события (`"kind"`: `message`, `edit`, `delete`, `react`). У `send` новых опций пока нет.

## Что видит relay, честно

- Ничего нового. Все четыре вида внутри Olm и дополняются до обычных размеров.
- Правка, удаление или реакция — короткое сообщение: relay видит сообщение наименьшего размера, точно как «ок». Он видит, что что-то отправлено и когда, как и с любым сообщением.

## Это не новый криптопротокол (правило 1)

Новые варианты открытого текста внутри Olm и случайные id для названия сообщений. Olm, vodozemac и relay не меняются.

## Отклонено

- **Цитировать текст внутри ответа.** Продлевает жизнь тексту исчезающего сообщения и удваивает текст в канале.
- **Любой эмодзи или текст как реакция.** Второй текстовый канал в обход лимитов; ширина колонок в терминале.
- **История правок.** Хранит то, что автор хотел заменить; приложение не хранит лишнего.
- **Запасной текст для старых клиентов** («👍 на ваше сообщение»): засоряет чат строками, похожими на сообщения.
- **Версия-рубеж вместо `Understands`** (всё новое с 0.9 для всех): контакты на 0.8 молча теряли бы сообщения.
- **`seq` как id сообщения**: начинается заново с каждой сессией Olm.

## Решения владельца (2026-11-17)

1. Срока для правки и удаления нет.
2. Шесть реакций и «не нравится» (красная стрелка вниз), рисуются termchat.app пиксельными спрайтами, а не системными эмодзи (раздел 5).
3. Пока только тексты; ответы, удаление и реакции для файлов — со следующим изменением `File`.
4. Разовая цена из раздела 6 принята: `Understands` и раздел 7 выходят вместе.
5. `recv --json` печатает правки, удаления и реакции как события (раздел 8).
