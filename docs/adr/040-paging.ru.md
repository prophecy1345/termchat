# ADR-040: вызов дежурного, подтверждение и эскалация

Статус: **предложено** (2026-11-22), ждёт решения владельца. English version: [040-paging.md](040-paging.md). Опирается на [ADR-032](032-ask.ru.md) (коды, закреплённые проверенные контакты) и [ADR-039](039-alert-webhooks.ru.md).

## Контекст

Алерт, который никто не прочитал, — не алерт. Инструменты дежурств (PagerDuty, Opsgenie) повторяют вызов, пока его не подтвердят, передают следующему, если никто не ответил, и сообщают, когда проблема ушла. У termchat все части есть: проверенные контакты, одноразовые коды из `ask`, daemon, который держит состояние. Этот ADR собирает их вместе, без SaaS и без выхода текста инцидента из сквозного шифрования.

## Решение

### 1. `termchat page`

```
termchat page --to alice --then bob --every 5m --escalate 15m --key disk-web1 \
    "Disk 95% full on web-1"
```

- Шлёт текст первому контакту со строкой `Reply "ack 3f9c2e81a07d6b54" to acknowledge.` Код — 16 строчных шестнадцатеричных цифр от ОС, как в ADR-032.
- Повторяет короткое напоминание каждые `--every` (по умолчанию 5 минут, не меньше 1), пока не подтвердят.
- Через `--escalate` (по умолчанию 15 минут) без подтверждения вызывает следующий контакт из `--then` (можно несколько, по порядку) с новым кодом и сообщает предыдущим «passed to bob». Предыдущие остаются вызванными: любой из них всё ещё может подтвердить.
- `ack <код>` с основного устройства любого вызванного контакта завершает вызов; остальные получают «acknowledged by alice». Команда выходит с `0`. Если цепочка исчерпана (`--give-up`, по умолчанию 2 часа), она выходит с `4` и сообщает всем «nobody acknowledged».
- Каждый контакт цепочки должен быть принят и проверен по отпечатку; основные ключи закрепляются при старте (ADR-032). Проверка ответа ровно как в ADR-032: исходный личный текст, подлинный отправитель и очередь, точная форма, после сохранения.
- Вызов идёт только контактам, никогда в группы: в группе нет одного человека, который подтверждает, а участники группы не закреплены и не проверены поодиночке.

### 2. Ключи и разрешение

- `--key` даёт имя инциденту. Второй `page` с уже открытым ключом не вызывает заново: он добавляет «still firing (2)» к открытому. Так мигающая проверка не будит одного человека дважды.
- `termchat resolve --key disk-web1` завершает вызов без подтверждения и сообщает всем вызванным «resolved after 14m». Разрешение после подтверждения шлёт ту же строку.
- Из приёмника вебхуков (ADR-039) маршрут может вызывать: `--route oncall=page:alice,bob:15m`. Сработавший алерт Alertmanager открывает вызов с ключом по его `fingerprint`; тот же алерт в статусе resolved его разрешает.

### 3. Время жизни

Вызовы живут в памяти daemon, как запросы `ask`. Перезапуск daemon их сбрасывает; документация говорит об этом, а `page` выходит с `6`, если его daemon пропал. Не больше 64 открытых вызовов на daemon; сверх этого отказ с `5`. Напоминания — обычные сообщения, отдельных заметок в истории нет.

| Код выхода | Значение |
| --- | --- |
| `0` | Подтверждено. |
| `2` | Неверные аргументы или неподдерживаемая платформа. |
| `3` | Контакт не найден или неоднозначен. |
| `4` | Никто не подтвердил до `--give-up`, или разрешено без подтверждения. |
| `5` | Контакт не подходит, слишком много вызовов или постоянная ошибка отправки. |
| `6` | Daemon недоступен или пропал. |

## Модель угроз

- **Подтвердить может любой, у кого в руках разблокированное основное устройство вызванного контакта**, как и с `ask`. Подтверждение только останавливает напоминания; на сервере оно ничего не разрешает.
- **Напоминания — это сообщения:** relay видит их ритм, как видит пульс `watch`. Текст остаётся зашифрованным.
- **Никакая команда не доходит до сервера** через вызов: `ack` только завершает вызов. Правило D2 сохраняется: украденный телефон не становится консолью.
- **Поток алертов:** ключи склеивают повторы; лимит 64 вызова и ограничение скорости из ADR-039 ограничивают, что может сделать сломанный источник алертов.

## Отклонено

- **Подтверждение в группе:** непонятно, кто подтвердил, а участники группы не закреплены.
- **Хранить вызовы на диске:** перезапуск, который молча заново вызывает старые инциденты, хуже, чем тот, что их сбрасывает и говорит об этом.
- **Эскалация звонком или SMS:** другие продукты и номера телефонов (правило 14).

## Что меняется

- `client`: команды `page` и `resolve`, состояние вызовов в daemon (с проверкой ответа из `ask`), маршруты `page:` в `hook`. Документация: «Вызов дежурного» в руководстве по скриптам (EN/RU), модель угроз.
- `core`, `proto`, `relay` и протокол `engine`: без изменений.
