# ADR-038 — Разнос подключений после разблокировки и пользователь, который ждёт

Статус — **предложено**, ждёт решения владельца. [English version](038-unlock-spread-and-waiting.md).

## Контекст

После разблокировки каждая связь, кроме связи основной личности, поднимается через случайные 0–30 с (ADR-014, для связи на каждый контакт сохранено в ADR-023). Так relay не может объединить очереди одного устройства по подключениям в одну и ту же секунду. Та же случайная пауза повторяется перед каждым переподключением.

Цена видна в живой проверке 2026-11-22: контакт написал через 7 с после разблокировки приложения для компьютера, а сообщение появилось примерно через 20 с, хотя строка состояния показывала «online» (связь основной личности). Приложение никак не объясняет ожидание. Сообщение, отправленное в этом окне, ждёт так же, с пометкой «sending». Пробуждение (`Relay::reconnect`, push через `Relay::check`) эту первую паузу не сокращает: оно сокращает только паузу после потерянного соединения.

Движок общий, поэтому так ведут себя все три приложения.

## Что защищает разнос

- **С Tor** у каждой связи своя цепочка (изоляция потоков), общего IP relay не видит. Остаётся время подключений, и именно разнос не даёт сгруппировать очереди устройства.
- **Без Tor** все связи идут с одного IP. ADR-014 уже говорит, что relay может связать их так. Разнос добавляет мало: немного защиты только там, где адрес общий у многих (NAT оператора, одна квартира).

## Варианты

A. **Связь, которую пользователь ждёт, пропускает остаток паузы:** открытый чат или группа, чат, в который он пишет, а на Android очередь, названная в push. Только эта связь; остальные сохраняют свои случайные паузы. Цена под Tor: если открыть чат сразу после разблокировки, связь этого контакта поднимется через пару секунд после связи основной личности, а именно эту корреляцию и прячет разнос. Отправка нового сигнала не даёт: запись relay видит в любом случае.

B. **Без разноса для прямых связей (Tor выключен).** Relay и так может сгруппировать их по IP (ADR-014). Убирает ожидание для тех, кто без Tor, почти без потерь. На Android и в настройке приложения для компьютера Tor включён по умолчанию, так что у большинства ожидание останется.

C. **Объяснить.** Пока связь чата ещё ждёт, в шапке чата написано «connecting…». Приватность не страдает; ожидание остаётся.

D. **Окно короче**, например 0–10 с. Меньше ожидание у всех, пропорционально слабее защита по времени под Tor.

## Рекомендация

B и C сейчас. A возможен позже как настройка, но по умолчанию он снимал бы разнос ровно тогда, когда пользователь активнее всего, сразу после разблокировки, поэтому без выбора владельца не рекомендуется.

## Что не меняется

Протокол, relay и формат на проводе. Меняется только момент, когда клиент подключается.
