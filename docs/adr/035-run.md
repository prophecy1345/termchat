# ADR-035 — Command reports with `termchat run`

Status — **accepted by the maintainer**. [Русская версия](035-run.ru.md).

## Context

A cron job or a long command often ends with `; termchat send alice "exit $?"`. That loses the duration and the error output, and a script that forgets it says nothing at all. `termchat run` wraps the command and sends one report when it ends: the result, how long it took and the last lines of output.

## Decision

### Command

```sh
termchat run --to alice -- ./backup.sh --full
termchat run --group Operations --name nightly-backup --failures-only -- ./backup.sh
```

- One recipient: `--to CONTACT`, `--group NAME` or `--group-id ID`, with the same matching and exit codes as `send`.
- Everything after `--` is the command. termchat starts it directly, without a shell. A shell pipeline goes through `sh -c '…'` written by the user.
- `--name LABEL` names the job in the report. Without it the report uses the program's file name (`backup.sh`), never the arguments.
- `--lines N` keeps the last N output lines, 10 by default, 0 to 50.
- `--failures-only` sends nothing when the command exits with 0.
- `--timeout SECS` limits only the send after the command ends, as for `send`. The command itself runs as long as it runs.

### Before, during and after

1. Before starting the command, termchat checks that it can send: a daemon for this `TERMCHAT_HOME` answers, or the password opens the identity. It resolves the recipient and checks that it can write there. On failure the command does not start, and termchat exits with the code `send` would use.
2. Without a daemon, termchat closes the identity again before starting the command, so a long job does not lock it.
3. The command inherits stdin, stdout, stderr's terminal and the environment. termchat copies stdout and stderr through unchanged and keeps the last N lines of both, in arrival order. Each kept line is cut at 500 bytes, and the whole tail at 12000 bytes, so memory stays bounded whatever the command prints. Bytes that are not UTF-8 are replaced.
4. When the command ends, termchat sends one text through the daemon or by opening the identity again:

   ```
   nightly-backup failed with exit 1 after 42m 10s on backup-box
   … last lines …
   ```

   The first line says `finished` for exit 0, `failed with exit N`, `was killed by signal N`, or `could not start: REASON`. The host is the system host name. Control characters are removed from the tail before sending, as `recv` does on output.

### Exit status

`run` exits with the command's status: its code, `128 + signal` when a signal ended it, or `127` when it could not start. Only when the command succeeded and the report failed does `run` return the send code instead (`1`, `4` or `5`), so a cron job notices a lost report. A send problem is always described on stderr.

### What is not sent

The environment and the command's arguments never go into the report. The report carries only the label, the outcome, the duration, the host name and the kept output lines.

## Threat model

The output tail is the risk: a command can print a token, a password or a path that reveals more than intended. The report goes end-to-end encrypted to one recipient the identity already writes to, and it lands in that chat history and its notifications, and on every device of a group. The guide tells users to set `--lines 0` or `--failures-only` for commands that may print secrets, and to keep the server identity separate as for `send`. termchat does not try to detect secrets in output: a filter would miss most of them and would read message content, which ADR-006 rules out.

Running the command is the user's own action under the user's own account. termchat adds no privileges, no shell and no remote trigger: nobody can start `run` by sending a message.

## Alternatives considered

- **A shell (`sh -c`) by default.** It makes quoting mistakes and injection easy when the command line is built from variables. Users who need a pipeline write `sh -c` themselves.
- **Sending the full command line.** Arguments often hold tokens (`curl -H "Authorization: …"`).
- **Keeping the identity open during the run.** A backup of several hours would block every other command of that identity without a daemon.
- **Returning termchat's own codes.** Callers of a wrapped command expect its status; `run` keeps it and reports send failures only when they would otherwise go unnoticed.

## Acceptance criteria

With a local relay and both with and without a daemon: a successful and a failing command each produce one report with the right first line and the last N lines; `--failures-only` sends nothing on 0; a killed command reports the signal and returns `128 + N`; a missing program reports `could not start` and returns 127; a wrong password, unknown contact or lost group access stops `run` before the command starts; output of several megabytes keeps memory bounded and the report under 16000 bytes; the report contains neither environment values nor arguments; `--lines 0` sends only the first line.
