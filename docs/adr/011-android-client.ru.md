# ADR-011: клиент для Android

Статус: **принято** (владелец, 2026-10-17). English version: [011-android-client.md](011-android-client.md).

## Контекст

termchat работает только в терминале. Приложение для Android должно уметь всё то же, что терминальный клиент (PLAN.md, «после MVP»), без второй реализации криптографии, протокола и файла состояния. ADR-001 уже выбрал UniFFI для мобильных; этот ADR определяет остальное.

## Решение

### 1. Один движок на Rust, две оболочки
- Новый крейт `crates/engine`: всё из нынешнего клиента, что не рисует экран.
  - Транспорт до relay (`client/src/lib.rs`).
  - Данные приложения и файл состояния (`data.rs`).
  - Правила паролей (`password.rs`).
  - Логика, которая сейчас внутри `app.rs::Main`: сохранение, отправка, приём, запросы, исчезающие сообщения, копия, пароли, пароль под принуждением, `WIPE`/`MOVED`, уведомление о новой версии.
  - Наружу — `Engine` с методами, типизированными событиями и ошибками вместо строк статуса.
- `crates/client` (TUI) становится оболочкой над `engine`; поведение не меняется.
- Новый крейт `crates/ffi`: привязки UniFFI к `engine` для Kotlin. Tokio работает внутри Rust, события приходят в Kotlin через callback-интерфейс.
- `core` и `proto` не меняются.

### 2. Приложение
- Kotlin + Jetpack Compose, в `android/`. minSdk 26 (Android 8).
- Без Google Play Services и Firebase: работает на телефонах без Google (GrapheneOS, LineageOS, Brax). Распространяется как подписанный APK в релизах GitHub (с подписями сборки) и через F-Droid.

### 3. На устройстве
- **Состояние.**
  - Тот же зашифрованный файл состояния (ADR-002, ADR-003) лежит в закрытой папке приложения.
  - Пароль под принуждением работает так же.
  - Android Keystore не используется: единственный ключ — пароль, поэтому копия восстанавливается на любом устройстве.
- **Экран.**
  - `FLAG_SECURE` на всех окнах: нельзя сделать снимок экрана, нет превью в списке недавних приложений.
  - Поля ввода просят клавиатуру не обучаться (`IME_FLAG_NO_PERSONALIZED_LEARNING`).
- **Блокировка.** Через 5 минут бездействия и через 5 минут в фоне, как автоблокировка в TUI.
- **Уведомления.** То же правило, что в ADR-008: «Новое сообщение» без имени и текста; по умолчанию выключены.
- **Копии.**
  - Пишутся и читаются через Storage Access Framework: пользователь сам выбирает флешку или папку.
  - Правило ADR-003 «стирание удаляет известные копии» действует.
  - Документ по content URI можно удалить, но нельзя сначала перезаписать. ADR честно это указывает.
- **Корни TLS.** На Android нет набора сертификатов, который читает `rustls-native-certs`. На Android транспорт использует возможность `webpki-roots` у tokio-tungstenite (список Mozilla, обновляется с каждым релизом).
- **Tor.** Будет позже, отдельным этапом. В первом релизе для Android Tor нет, и настройки об этом говорят.

### 4. Чего приложение не делает
Только текст (правило 9):
- никаких вложений, звонков и видео;
- нет доступа к контактам телефона;
- нет номера телефона.

Камера используется только чтобы отсканировать QR-код приглашения и только после нажатия «сканировать».

### 5. Внешний вид
По мотивам мессенджера Brax Wink (образец владельца):
- **Цвета и шрифты.** Почти чёрный фон, моноширинный шрифт для сообщений, строк статуса и поля ввода, жирный рубленый шрифт для имён. Акцентный цвет — лайм.
- **Шапка чата:**
  - квадратный аватар с инициалами;
  - имя;
  - строка статуса лаймовыми заглавными с коротким отпечатком, например `ENCRYPTED · 75392`;
  - у непроверенного контакта — `NOT VERIFIED · 75392` предупреждающим цветом.
- **Пузыри.** Наши тёмно-оливковые, чужие тёмно-серые, у обоих небольшие скругления.
- **Системные строки** (запрос принят, контакт ушёл, переписка начата заново) — по центру, в тонкой рамке.
- **Строка ввода:**
  - квадратная кнопка таймера (значок капли) переключает исчезающие сообщения, как Ctrl+T;
  - поле в рамке `Encrypted message`;
  - плоская кнопка `SEND`.
- **Что убрано из образца:** кнопки вложений и звонков.

Темы TUI остаются; вид Android становится ещё и темой TUI, чтобы оба клиента могли выглядеть одинаково.

### 6. Новые зависимости (каждую обосновать при добавлении)
- `uniffi` (привязки).
- Возможность `webpki-roots` у tokio-tungstenite (корни TLS на Android).
- AndroidX/Compose.
- `zxing-core` чтобы рисовать и читать QR-код. Он на чистой Java, без Google ML Kit.

## Метаданные, честно

Приложение ходит к тому же relay так же, как терминальный клиент: для relay и наблюдателя за сетью ничего нового.

Сам Android знает, что приложение установлено и когда оно выходит в сеть. Операционная система и установленные приложения вне нашей модели угроз, как и на компьютере.

Доставка в фоне — отдельное решение (ADR-012).
