# ADR-018: десктопный GUI-клиент

Статус: **принято** (владелец, 2026-11-06). English version: [018-desktop-gui.md](018-desktop-gui.md).

## Контекст

На компьютере termchat работает только в терминале. Терминальный интерфейс
нравится не всем. ADR-011 уже разделил клиент на `crates/engine` (всё, кроме
отрисовки) и тонкие оболочки: TUI и приложение для Android. Окно на десктопе
станет третьей оболочкой над тем же движком. Криптография, протокол, файл
состояния и relay не меняются.

Владелец решил (2026-11-06) писать его на Rust, а не переносить Compose-интерфейс
Android на Compose Desktop.

## Решение

### 1. Новый крейт, отдельный бинарник
- `crates/desktop`, бинарник `termchat-gui`, оболочка над `termchat-engine`,
  как `crates/client`.
- Бинарник TUI остаётся как есть и не тянет GUI-зависимостей.
- Код, нужный обеим оболочкам, переезжает из `crates/client` в `engine`:
  - `settings.rs` (файл настроек из ADR-008);
  - звуковая часть `notify.rs`;
  - константа автоблокировки.
  Поведение TUI не меняется.
- `#![forbid(unsafe_code)]`, как во всём workspace.

### 2. Тулкит: egui (eframe)
| | egui / eframe | iced | slint |
|---|---|---|---|
| Лицензия | MIT / Apache-2.0 | MIT | GPLv3, royalty-free или коммерческая |
| Экранные чтецы | да (AccessKit) | нет, на момент написания | да |
| Код UI | обычный Rust | обычный Rust (в стиле Elm) | свой язык `.slint` и компилятор |
| Рендерер | OpenGL (`glow`) или wgpu | wgpu или tiny-skia | свой |

Выбран egui: обычный Rust, свободная лицензия, поддержка экранных чтецов и
меньше всего кода UI для окна чата. Он не выглядит нативно, но у termchat всё
равно свой вид (раздел 5). Рендерер `glow`, а не wgpu, ради меньшего дерева
зависимостей. Точные features и версии фиксируются при добавлении
зависимости и проверяются `cargo deny`.

**Отклонено.**
- Tauri и любой webview: HTML-движок внутри мессенджера, большая поверхность
  атаки и против духа ADR-017 (никакого рендеринга).
- GTK (gtk4-rs): нужен установленный GTK на macOS и Windows.
- Compose Desktop: JVM-рантайм в каждом архиве (решение владельца).

### 3. На компьютере
- **Состояние.** Тот же зашифрованный файл состояния и `settings.json` в
  `~/.termchat/`. GUI и TUI могут открывать один аккаунт, но не одновременно:
  два запущенных клиента двигали бы Olm-сессии каждый сам и затирали бы
  состояние друг друга. Сейчас этому ничего не мешает (два TUI уже могут так
  сделать). Движок берёт эксклюзивную блокировку файла состояния
  (`std::fs::File::try_lock`, без новой зависимости), и второй клиент пишет
  «termchat уже открыт».
- **Пароль.** Как в TUI, пароль остаётся единственным ключом. Связка ключей ОС
  не используется, поэтому бэкап восстанавливается где угодно.
- **Заголовок окна.** Всегда просто `termchat`, никогда не имя контакта:
  заголовок видят другие программы, панель задач и переключатель окон.
- **Блокировка.** Через 5 минут бездействия, как в TUI. Сворачивание окна
  его не блокирует.
- **Уведомления.** Первая версия: только карточка в окне и звук из ADR-008.
  Без системных уведомлений: ADR-008 и так выключает их по умолчанию, потому
  что ОС хранит их историю. Их можно добавить позже отдельным решением.
- **Буфер обмена.** Только явные копирование и вставка в текстовых полях
  (это делает egui). Сам termchat в буфер ничего не кладёт.
- **Документы (ADR-017).** Сохраняются и выбираются через файловый диалог.
  Без превью, без открытия, без миниатюр.
- **Tor.** Arti через feature `tor` движка, lyrebird в архивах, как для TUI
  (ADR-004, ADR-015).

### 4. Чего он не делает
Те же ограничения, что у других клиентов (правила 9, 14, 15): без рендеринга
текста сообщений, без превью ссылок, без картинок, без звонков, без
адресной книги, без поиска пользователей.

### 5. Внешний вид
Вид Android (ADR-011, раздел 5): почти чёрный фон, моноширинные сообщения,
лаймовый акцент, заголовок `ENCRYPTED · 75392` / `NOT VERIFIED · 75392`,
те же пузыри и строка ввода. Темы TUI из `engine::themes` тоже доступны.

### 6. Распространение
- Архивы для macOS, Linux и Windows в релизах GitHub, с аттестациями сборки,
  рядом с архивами TUI.
- **Без платной подписи** (владелец, 2026-11-06). Ни Apple Developer ID
  ($99 в год, частным лицам взнос не прощают), ни сертификата подписи кода
  для Windows. На macOS сборки подписаны только ad-hoc: это и так делает
  Rust-линкер, и этого требует Apple Silicon.
- **Основной путь: существующий установщик**, `scripts/install.sh` и
  `scripts/install.ps1`. Они уже сверяют архив с `SHA256SUMS`. Для GUI они
  ещё:
  - macOS: кладут `termchat.app` в `~/Applications`;
  - Linux: кладут `termchat-gui` в `~/.local/bin`, а запись `.desktop` с
    иконкой в `~/.local/share`;
  - Windows: добавляют пункт в меню «Пуск».
  У файлов, скачанных `curl`, нет атрибута карантина, поэтому Gatekeeper не
  останавливает первый запуск. Herdr ставит своё приложение так же
  (проверено 2026-11-06). В отличие от Herdr, termchat не обновляет себя сам
  (ADR-010: только уведомление).
- **Homebrew.** Формула `termchat-gui` в нашем tap. Формулы тоже не попадают
  в карантин. Для официальных casks Homebrew нужна нотаризация, поэтому cask
  не делаем.
- **Простое скачивание** архива для macOS со страницы релиза тоже работает,
  но первый запуск macOS запрещает. На macOS 15 и новее пользователь один раз
  открывает «Системные настройки» → «Конфиденциальность и безопасность» →
  «Всё равно открыть». README об этом говорит. Ни `.dmg`, ни кнопки «Скачать
  для Mac»: без нотаризации она вела бы прямо в этот запрет.
- **Windows.** Неподписанный `.exe`, скачанный браузером, показывает
  предупреждение SmartScreen («Подробнее» → «Выполнить в любом случае»);
  README об этом говорит.
- Flatpak и winget позже, отдельными шагами.

### 7. Новые зависимости
- `eframe` / `egui` с features `glow` и `accesskit`.
- `rfd` для нативного файлового диалога (документы, бэкапы), если своего
  диалога egui не хватит.
Каждая обосновывается в своём коммите и проверяется `cargo deny`.

## Решено с владельцем (2026-11-06)
1. **Без защиты от захвата экрана.** На Android используется `FLAG_SECURE`.
   На десктопе аналоги (`NSWindow.sharingType` на macOS,
   `SetWindowDisplayAffinity` на Windows; на Linux/X11 ничего) требуют
   платформенных вызовов с `unsafe` или ещё одной зависимости, а новые API
   захвата в macOS их соблюдают не всегда. GUI не пытается; README говорит,
   что скриншоты и запись экрана видят окно.
2. **Без платной подписи**, см. раздел 6.

## Уточнено по ходу работы (2026-11-06)
- **Сборки для Linux на glibc 2.28, а не musl.** Статическая программа на musl
  не может подгрузить системные OpenGL, X11 и Wayland. GUI собирается под
  `*-unknown-linux-gnu` с glibc 2.28 (Debian 10, Ubuntu 20.04, RHEL 8) и
  подгружает libwayland во время работы, как X11 (`winit/wayland-dlopen`),
  поэтому связан только с glibc. Сборка x86_64 проверяется на
  воспроизводимость, как у терминального клиента. Терминальный клиент
  остаётся статическим на musl.
- **Архивы** называются `termchat-gui-<tag>-<target>`, lyrebird внутри. На
  macOS в архиве `termchat.app` с ad-hoc подписью `codesign --sign -`
  (бесплатно; нотаризацию она не заменяет). На Linux — запись `.desktop` и
  иконка.
- **Установщики**: с `TERMCHAT_GUI=1` `install.sh` и `install.ps1` ставят
  приложение вместо терминального клиента. Release workflow проверяет оба
  варианта.
- **Homebrew**: формула `termchat-gui` держит lyrebird рядом с программой, а не
  в `bin`, чтобы не конфликтовать с терминальным клиентом.
- **Windows**: за приложением нет окна консоли; своей иконки у `.exe` пока нет
  (для неё нужен компилятор ресурсов, это отдельный шаг).
- **Настройки**: в `settings.json` рядом с `theme` терминала лежит
  `desktop_theme`, у каждого свой вид.
- **Общий код** переехал в движок по мере надобности: настройки, звук,
  автоблокировка, защита от core dump, блокировка файла состояния, короткие
  подписи времени, раскрытие путей, чтение документа для отправки, заметки к
  версии.

## Метаданные, честно

GUI общается с relay так же, как TUI: для relay и наблюдателя в сети ничего
нового.

GUI оставляет на компьютере больше следов, чем терминал:
- ОС знает, что есть окно `termchat-gui` и когда оно на переднем плане;
- текст проходит через тулкит, драйвер GPU и оконную систему, у которых свои
  копии в памяти; `Zeroize` наших буферов до них не дотягивается;
- скриншоты и запись экрана видят окно (см. выше).

Операционная система и другие установленные программы вне модели угроз, как
для TUI и Android.
