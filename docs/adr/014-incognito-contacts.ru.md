# ADR-014: инкогнито-контакты, отдельная личность на каждый контакт

Статус: **принято** (владелец, 2026-10-19). English version: [014-incognito-contacts.md](014-incognito-contacts.md).

## Контекст

У аккаунта одна личность: один ключ. Он есть в каждом приглашении, каждом запросе и каждом отпечатке. Отсюда два следствия:
- **Контакты могут вас связать.** Двое контактов, сравнив номера безопасности, поймут, что говорят с одним человеком, каким бы ни был ник у каждого.
- **Relay может связать ваши контакты.** Он видит, что все они пишут одному ключу, то есть знает весь ваш круг общения.

Разный ник для разных контактов не прячет ни того ни другого, поэтому его не делаем (владелец, 2026-10-19). В SimpleX режим инкогнито даёт каждому контакту отдельную личность. Этот ADR делает то же самое, используя только то, что в termchat уже есть: личность — это Olm-аккаунт vodozemac и аккаунт на relay.

## Решение

### 1. Профили
- **Профиль** — одна личность:
  - свои ключи Ed25519 и Curve25519 (свой Olm-аккаунт);
  - свои prekeys;
  - свой ник;
  - свой аккаунт и своё соединение на relay.
- Каждый контакт принадлежит ровно одному профилю.
- **Основной профиль** — та личность, которая есть у аккаунта сейчас. Обычные приглашения, публичное приглашение и все существующие контакты работают через него. Для них ничего не меняется.
- **Инкогнито-профиль** создаётся для одного контакта и используется только с ним.

### 2. Инкогнито-приглашения (по выбору)
- В окне приглашения появляется третий вид — **инкогнито**. При показе такого приглашения:
  - создаётся новый профиль с новым ником, который вводит пользователь; если оставить поле пустым, будет случайная пара слов;
  - prekeys профиля публикуются на relay;
  - показывается одноразовое приглашение этого профиля (ADR-013) со своим кодом.
- Когда друг его добавляет, запрос приходит только в этот профиль.
- При добавлении чужого приглашения тот же выбор: **«добавить инкогнито»** создаёт новый профиль и отправляет запрос от него.
- Инкогнито-профиль без контакта удаляется (`Unregister`, ADR-009), когда его приглашение отозвано или вытеснено более новыми. Таких ожидающих профилей не больше 5.

### 3. Профили на relay не пересекаются
- У каждого профиля своё WebSocket-соединение, и оно аутентифицирует только свой ключ. Ни в одном кадре не встречаются два профиля сразу.
- **Через Tor** соединение каждого профиля идёт по своей цепочке (изоляция потоков в arti). Тогда relay не может по сети понять, что два профиля — с одного устройства.
- **Без Tor** все профили подключаются с одного IP-адреса, и relay может связать их по нему. Приложение пишет об этом рядом с переключателем и советует Tor для инкогнито-контактов.
- **Время.** После разблокировки и перед каждым переподключением каждый профиль ждёт случайные 0–30 с, чтобы профили не появлялись и не пропадали в одну и ту же секунду.
- **Нумерация.** Каждый профиль нумерует свои кадры `Send` сам, начиная со случайного числа. Общий счётчик показал бы relay, какие ключи принадлежат одному человеку. (Найдено ревью безопасности при реализации.)
- **Push (ADR-012).** Каждый профиль регистрирует свой экземпляр UnifiedPush со своим endpoint. Общий endpoint связал бы профили на relay.

### 4. Жизненный цикл
- **Удаление инкогнито-контакта** отправляет прощание (ADR-009), затем `Unregister` для его профиля и стирает профиль. Relay забывает этот ключ.
- **WIPE / MOVED:** каждый профиль прощается со своими контактами и снимается с регистрации, как основной сейчас.
- **Пароль под принуждением** стирает все профили вместе с файлом состояния. Ничего не отправляется, как и сейчас.
- **Бэкап** содержит все профили, их ключи и контакты в том же зашифрованном файле.
- **Жалоба и блокировка** действуют внутри профиля этого контакта.

### 5. Чего не делаем
- Инкогнито **не включено по умолчанию**.
  - Каждый профиль — это ещё одно соединение, а через Tor — ещё одна цепочка. При большом числе контактов на телефоне это стоит батареи и времени запуска.
  - Пользователь решает для каждого контакта сам.
- **Sealed sender (B3) пока не делаем.**
  - Sealed sender прятал бы от relay отправителя внутри пары ключей.
  - С инкогнито-профилями каждая пара — это два ключа, которые больше ни для чего не используются, так что прятать одну сторону почти бесполезно.
  - Для контактов основного профиля relay по-прежнему видит граф. Тем, кому нужно больше, отвечает инкогнито.
  - Это заменяет этап B3 плана. Владелец может вернуть его позже.

## Метаданные, честно

- **Relay** видит пару ключей, которые общаются только друг с другом. Через Tor и при раздельных цепочках он не может по сети связать эту пару с другими вашими ключами. Между профилями он всё ещё может догадаться по совпадениям:
  - время подключения, даже со случайными задержками;
  - версия приложения, которая есть у немногих;
  - время сообщений.
- **Блокировка приложения** закрывает соединения всех личностей в один момент: ключи должны уйти из памяти. Relay, который за этим следит, может связать личности, которые раз за разом отключаются вместе.
- **WIPE** ждёт, пока подключатся все личности, и завершается, только когда relay подтвердил, что забыл каждую из них, или по таймауту.
- **Контакт** видит ключ, ник и отпечаток, которые больше нигде не используются. Связать их с другими вашими контактами он не может, если вы сами не скажете или вас не выдаст текст.
- **Устройство** хранит все профили. Тот, кто его разблокирует, увидит их все.

## Это не новый криптопротокол (правило 1)

- Каждый профиль — обычный аккаунт vodozemac, который используется так же, как основной.
- Из основного ключа ничего не выводится, и криптографически ключи между собой не связаны.
- Новые примитивы не комбинируются.

## Отклонено

- **Разный ник при одном ключе:** не прячет ничего ни от контактов, которые сравнивают ключи, ни от relay.
- **Выводить ключи профилей из основного ключа:** по одному ключу можно было бы найти остальные, и это была бы самописная криптография (правило 1).
- **Много профилей через одно соединение:** relay увидел бы их вместе.
- **Инкогнито для всех по умолчанию:** на телефонах это слишком дорого для варианта по умолчанию.

## Зависимости

Новых нет. В arti уже есть изоляция потоков (`IsolationToken`), а UnifiedPush поддерживает несколько экземпляров на одно приложение.
