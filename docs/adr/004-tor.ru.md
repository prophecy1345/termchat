# ADR-004: Tor

Статус: принято, реализовано в M6. Дата: 2026-10-15. English: [004-tor.md](004-tor.md).

## Контекст

Relay видит IP каждого клиента (в памяти, ради лимитов). Провайдер видит, что пользователь ходит на relay. Tor закрывает и то и другое. От глобального наблюдателя, который сопоставляет время трафика, Tor не защищает, и это остаётся в «Не защищаемся».

Подключаться к relay через выходной узел Tor плохо: у выходных узлов общие IP, и лимиты по IP задевают всех их пользователей сразу. Поэтому Tor-клиенты ходят на **onion-адрес** relay.

## Решение

### Relay: никакого Tor-кода, только C tor рядом
- Оператор ставит системный `tor` и публикует onion-сервис, который ведёт на отдельный локальный порт relay:

  ```
  HiddenServiceDir /var/lib/tor/termchat/
  HiddenServicePort 80 127.0.0.1:8081
  HiddenServicePoWDefensesEnabled 1
  ```

- C tor проверен годами, а встроенная в Tor защита onion-сервисов от DoS (proof-of-work, `HiddenServicePoWDefensesEnabled`) снимает вопрос о своём proof-of-work.
- **Важно (найдено при проверке):** модуль proof-of-work есть не во всех сборках `tor`, он требует сборки с `--enable-gpl`. В Homebrew его нет, и `tor` с этой строкой просто не запустится. В пакете Debian/Ubuntu и в сборках Tor Project он есть. Без него onion-сервис работает, но без этой защиты.
- Relay получает флаг `--onion-listen 127.0.0.1:8081`. Все подключения на этот порт приходят с `127.0.0.1`, поэтому для них:
  - лимиты по IP не применяются;
  - вместо них общий бюджет на все onion-подключения: не больше 2000 соединений и 200 новых регистраций в час (`Limits`);
  - лимиты по ключу работают как обычно.
- `--host` можно указать несколько раз (`relay.example.org` и `xxxx.onion`): клиент подписывает тот адрес, по которому пришёл.

### Клиент: Arti внутри
- `arti-client` 0.47 с функциями `tokio`, `rustls` (без OpenSSL), `onion-service-client`, `compression`, `static-sqlite`.
- WebSocket поверх потока Arti: `tokio-tungstenite::client_async` с `ws://xxxx.onion/`. TLS поверх onion не нужен: onion-адрес сам аутентифицирует сервер и шифрует канал.
- Состояние Arti (guards, кеш каталога) хранится в `~/.termchat/arti`, права `0700`.
- **Без утечки мимо Tor:** если Tor включён, клиент никогда не подключается напрямую, даже если Tor не поднялся. В строке состояния — «connecting via Tor…».
- Сборка: cargo-функция `tor` у клиента. Она включена в официальных релизах и выключается для минимальной сборки.

### Приглашения
- В `Invite` появляется необязательное поле `onion_url`. Приглашение принимается, если совпадает хотя бы один из адресов relay: обычный или onion. Так пользователи с Tor и без Tor одного relay могут добавлять друг друга.
- Формат ещё не выпущен ни в одном релизе, поэтому версия остаётся 1. После первого релиза (M6) любое изменение формата повышает `version`.

### Настройка
- При первом запуске клиент спрашивает адрес relay и, если у relay есть onion, адрес onion и «Use Tor? (y/n)».
- Переключить можно в настройках (Ctrl+P). Включение Tor запрещает прямые подключения сразу; выключение показывает предупреждение, что relay увидит IP.

## Цена

- **Зависимости:** Arti — это примерно 250 крейтов и +10–15 MB к бинарнику. Все под MIT/Apache, `cargo deny` проверит. Поэтому Tor — отдельная cargo-функция.
- **Задержка:** первое подключение 10–30 секунд (загрузка каталога), дальше 1–3 секунды на сообщение.
- **Сложность для оператора:** relay с onion-адресом требует системный `tor`. Без него relay работает как раньше.

## Что меняется в модели угроз
- В «Защищаемся» (опционально): IP пользователя не видят ни relay, ни провайдер, если включён Tor.
- В «Не защищаемся» остаются глобальный наблюдатель и сопоставление времени. Relay по-прежнему видит ключи и время сообщений.

## Отвергнуто
- **Onion-сервис внутри relay через Arti (`onion-service-service`):** менее проверен, чем C tor; оператору проще и надёжнее поставить системный `tor`.
- **Клиент через системный `tor` (SOCKS5):** лишняя установка для пользователя; Arti встраивается в бинарник.
- **Свой proof-of-work на регистрацию:** у Tor он уже есть для onion-сервисов.

## Решения по открытым вопросам
1. Tor выбирается на экране первого запуска, по умолчанию предложено «y».
2. Функция `tor` включена в официальные релизы (один бинарник).

## Что получилось
- Release-бинарник клиента: 20,7 MB, около 640 крейтов в дереве.
- Новые лицензии в дереве (все совместимы с AGPL): CC0-1.0, Unlicense, MPL-2.0.
- Исключения в `cargo deny` с обоснованием: RUSTSEC-2024-0436 (`paste`, proc-macro на этапе сборки), RUSTSEC-2023-0071 (`rsa`, атака на операции с закрытым ключом, которых у Tor-клиента нет).
- Проверено вживую: relay за системным `tor` 0.4.9, клиент через Arti подключился за 6 секунд, сообщения в обе стороны с клиентом без Tor доходят примерно за 2 секунды, переключение Tor в настройках.
